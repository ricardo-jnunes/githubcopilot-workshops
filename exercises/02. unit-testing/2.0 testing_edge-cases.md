# Testing Edge Cases

GitHub Copilot identifies edge cases by analyzing code context, boundary thresholds, and potential logical failures. When generating unit tests, it focuses on areas where applications commonly break due to unexpected or extreme inputs.

Edge cases Tests are tests for boundary conditions (e.g., negative values for deposits or withdrawals, withdrawing more than the available balance). They are specific, unusual testing scenarios that evaluate how your application handles data boundaries, extreme inputs, or unexpected system errors.

# Exercise Scenario

You're a developer working in the IT department of your local community. The backend systems that support the public library were lost in a fire. Your team needs to develop a temporary solution to help the library staff manage their operations until the system can be replaced. Your team chose GitHub Copilot to accelerate the development process.

You have an initial version of the library application that includes a unit test project named UnitTests. You need to ensure additional edge case tests using GitHub Copilot.

This exercise includes the following tasks:

- Examine the approach to unit testing implemented by the UnitTests project.
- Extend the UnitTests project to add an edge case for Library.Infrastructure project.
