# Create and Integrate a Local MCP Server with VS Code

## Workshop objectives

By the end of this exercise, you will be able to:

- understand the role of an MCP server and an MCP client;
- create a local MCP server with Node.js;
- expose a small tool to GitHub Copilot through MCP;
- configure and run the server from VS Code;
- test the integration while keeping the tool's access limited and explicit.

## What is MCP?

The Model Context Protocol (MCP) is a standard way for an AI client to discover and call tools provided by an external server.

In this exercise:

- VS Code is the MCP client;
- GitHub Copilot uses the client to discover available tools;
- the local Node.js process is the MCP server;
- the server exposes a `list_workspace_files` tool.

The server communicates through standard input and standard output using the MCP protocol. Do not write diagnostic messages to standard output because that can corrupt the protocol messages. Write diagnostics to standard error instead.

## Prerequisites

- VS Code with GitHub Copilot enabled;
- Node.js 18 or later;
- a folder opened as a VS Code workspace;
- permission to create files in the workspace.

This example uses the official MCP TypeScript SDK. Check the SDK documentation for the current package version and API details before using the example in production.

## Exercise 1: Create the local server

Create a separate folder for the server and initialize a Node.js project:

```powershell
New-Item -ItemType Directory -Force tools/local-mcp-server
Set-Location tools/local-mcp-server
npm init -y
npm install @modelcontextprotocol/sdk zod
npm install --save-dev typescript tsx @types/node
```

Create `tools/local-mcp-server/src/server.ts` with the following content:

```typescript
import { existsSync, readdirSync } from "node:fs";
import { relative, resolve, sep } from "node:path";
import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";
import { z } from "zod";

const workspaceRoot = resolve(process.env.WORKSPACE_ROOT ?? process.cwd());

const server = new McpServer({
  name: "local-workspace-tools",
  version: "1.0.0",
});

server.registerTool(
  "list_workspace_files",
  {
    description: "List files in a permitted directory below the workspace root.",
    inputSchema: {
      directory: z.string().default("."),
    },
  },
  async ({ directory }) => {
    const target = resolve(workspaceRoot, directory);
    const relativeTarget = relative(workspaceRoot, target);

    if (relativeTarget === ".." || relativeTarget.startsWith(`..${sep}`)) {
      return {
        content: [{ type: "text", text: "The requested directory is outside the workspace." }],
        isError: true,
      };
    }

    if (!existsSync(target)) {
      return {
        content: [{ type: "text", text: "The requested directory does not exist." }],
        isError: true,
      };
    }

    const files = readdirSync(target, { withFileTypes: true })
      .map((entry) => (entry.isDirectory() ? `${entry.name}/` : entry.name))
      .sort();

    return {
      content: [{ type: "text", text: files.join("\n") || "The directory is empty." }],
    };
  },
);

const transport = new StdioServerTransport();
await server.connect(transport);
```

Add a start script to `tools/local-mcp-server/package.json`:

```json
{
  "scripts": {
    "start": "tsx src/server.ts"
  }
}
```

Run the server manually to check that it starts without a TypeScript error:

```powershell
npm start
```

The process waits for MCP messages, so stop it with `Ctrl+C` after confirming that no startup error was reported.

## Exercise 2: Configure the server in VS Code

At the root of the workspace, create `.vscode/mcp.json` if it does not already exist:

```json
{
  "servers": {
    "local-workspace-tools": {
      "type": "stdio",
      "command": "npm",
      "args": [
        "start"
      ],
      "cwd": "${workspaceFolder}/tools/local-mcp-server",
      "env": {
        "WORKSPACE_ROOT": "${workspaceFolder}"
      }
    }
  }
}
```

The important settings are:

- `type: "stdio"` tells VS Code to launch a local process and communicate through standard input and output;
- `command` and `args` define how the server starts;
- `cwd` points to the server project;
- `WORKSPACE_ROOT` limits the example tool to the opened workspace.

Do not put passwords, access tokens, or other secrets in `.vscode/mcp.json`. Keep local-only configuration out of source control when it contains sensitive values.

## Exercise 3: Start and test the server

1. Open the Command Palette with `Ctrl+Shift+P`.
2. Run `MCP: List Servers` and select `local-workspace-tools`.
3. Start the server and inspect its output if VS Code reports an error.
4. Open GitHub Copilot Chat and ask:

   > Use the `list_workspace_files` tool from the local-workspace-tools MCP server to list the files in the `exercises` directory. Do not modify anything.

5. Confirm that the response contains entries from the workspace and that no files were changed.

You can also test the boundary enforced by the server:

> Use the `list_workspace_files` tool to list the directory `../`. Do not modify anything.

The server should reject a path outside the workspace root.

## Exercise 4: Improve the tool safely

Extend the server with one small read-only capability, such as:

- returning the first 20 lines of a selected Markdown file;
- finding Markdown files below a selected directory;
- reporting the number of files in a directory.

Before implementing the tool, define:

- its name and description;
- its input schema;
- the directories or file types it may access;
- the error returned for invalid input;
- whether it only reads data or can change the workspace.

Then ask Copilot to use the new tool with a read-only request. Review the generated code and test invalid paths before trusting the integration.

## Troubleshooting

### The server does not appear in VS Code

- Confirm that `.vscode/mcp.json` is at the workspace root.
- Check that the JSON is valid.
- Confirm that Node.js and `npm` are available in the VS Code environment.
- Run the command from `tools/local-mcp-server` manually.
- Open the MCP server output in VS Code and inspect the reported error.

### The server starts and immediately stops

- Check that the server uses `StdioServerTransport`.
- Ensure protocol messages are not mixed with logs on standard output.
- Send diagnostic messages to `console.error`, not `console.log`.

### The tool returns an access error

- Confirm the value of `WORKSPACE_ROOT`.
- Use a path relative to the workspace root.
- Keep the path validation in place; do not remove it just to make a test pass.
